# Эксплуатация КИП и А

Основной вариант размещения на общем сервере описан в [инструкции без Docker](DEPLOYMENT.md). Ниже — работа приложения, интеграции и дополнительный вариант контейнерного запуска.

Рабочий проект на **React + TypeScript + Vite** и **Python + FastAPI**. Данные хранятся в SQLite через `aiosqlite`. Готовая сборка интерфейса обслуживается тем же FastAPI-приложением; отдельный Node.js-сервер для production не нужен.

## Быстрый запуск

Требуются Python 3.12+ и Node.js 22+.

```bash
python3 -m venv .venv
.venv/bin/pip install -r backend/requirements.lock
npm ci
python3 scripts/setup.py
npm run build
.venv/bin/python -m uvicorn backend.app.main:app --host 127.0.0.1 --port 8000
```

- Магазин: <http://127.0.0.1:8000>
- Администратор: <http://127.0.0.1:8000/admin>
- Документация API: <http://127.0.0.1:8000/api/docs>

`setup.py` генерирует случайный пароль, сохраняет **только PBKDF2-хеш** в `.env`, а первоначальный пароль — в локальный `admin-access.txt` с правами `0600`. Перенесите пароль в менеджер паролей и удалите этот файл. Эти файлы исключены из Git и Docker. Повторный запуск не перезаписывает существующий `.env`. Для уже подготовленной рабочей папки настройки созданы.

Для разработки запустите backend и `npm run dev` в двух терминалах. Vite проксирует `/api` на `127.0.0.1:8000`. Если порт 5173 занят, задайте свободный порт и добавьте **точный origin** в `ALLOWED_ORIGINS`, затем перезапустите backend.

## Что реализовано

- Русский интерфейс, адаптивная мобильная версия, светлая и тёмная темы.
- Информация о магазине, исходное фото фасада, контакты, ссылка на карточку 2ГИС.
- Категории, поиск, сортировка, фильтры наличия и скидок, избранное.
- Карточка товара: описание, характеристики, изображение, бренд, варианты с собственной ценой и остатком.
- Услуги, включая сборку электрощитов: отдельный тип позиции, варианты и цены, добавление в корзину, заказы и аналитика. Единица `усл`, целое количество, складской остаток не списывается. Начальная цена услуги демонстрационная; комплектующие оплачиваются отдельно.
- Сортировка с меню, согласованным с активной темой, управлением клавиатурой и закрытием по Escape.
- У автомата 1P в демонстрационном каталоге предусмотрены варианты от 3 до 100 А.
- Единицы продажи (`шт`, `м`, пользовательские единицы), шаг количества и отдельный справочник характеристик. Вольт — `В`, ватт — `Вт`, ампер — `А`.
- Скидка включается отдельным флагом. Выключенная скидка не влияет на цену.
- Корзина и избранное сохраняются в браузере. Имя принимает буквы, пробелы, апостроф и дефис. У телефона статический `+7` и 10 цифр: всего 11 цифр, либо 12 символов вместе с `+`. Номера Казахстана начинаются с `+76` или `+77`.
- Самовывоз или доставка с городом, адресом, комментарием и согласием на обработку данных. Стоимость доставки не включена в товары и согласуется менеджером.
- Заказ сохраняется транзакционно. Сервер берёт актуальные цены из базы, применяет скидку и рассчитывает суммы. Клиент не может передать собственную цену. Денежные суммы округляются до целого тенге.
- Остаток резервируется при создании заказа. Недостаток любого товара отменяет всю транзакцию. Повтор запроса с тем же ключом не создаёт дубликат и не списывает остаток повторно.
- Отмена заказа возвращает остаток один раз. Статусы: новый → подтверждён → выполнен; новый / подтверждён → отменён. Выполненные и отменённые заказы окончательны.
- Защищённая админ-панель: создание, просмотр, редактирование и удаление товаров, загрузка PNG/JPEG/WebP до 4 МБ, категории и единицы, управление заказами, ссылка на магазин.
- Редактирование телефона, адреса, графика, описания и условий доставки. Название магазина и исходная ссылка 2ГИС защищены от изменений через API настроек.
- Аналитика за 7 и 30 календарных дней в часовом поясе Алматы (UTC+5): выручка, выполненные заказы, количество отдельно по каждой единице, дневной график и лидеры по выручке. Новые заявки не считаются продажами.
- В админ-панели телефон открывает WhatsApp с приветствием, номером и суммой заказа, вопросом о способе оплаты.
- Серверная очередь уведомлений Telegram и WhatsApp с повторными попытками и сохранением прогресса длинных сообщений.
- Администратор редактирует тексты Telegram, уведомления магазину в WhatsApp и сообщения клиенту. Предпросмотр использует вымышленные данные и ничего не отправляет.
- Смена пароля с проверкой старого, требованиями к сложности, защитой от перебора и завершением всех сессий.

## Пароль и защита входа

В панели откройте **Настройки магазина → Безопасность**. Введите старый пароль, новый и его подтверждение. Новый пароль содержит минимум 8 символов, одну заглавную букву, цифру и специальный символ (пробел не считается). Требования проверяются в интерфейсе и на сервере. Новый пароль должен отличаться от старого.

После смены все сессии, включая текущую, закрываются. Новый PBKDF2-SHA256-хеш с уникальной случайной солью и 600 000 итераций сохраняется в SQLite и имеет приоритет над первоначальным `.env`. Перезапуск сервера не возвращает старый пароль. Файл `admin-access.txt` содержит только первоначальные данные и после смены не обновляется. Сессии действуют 8 часов, в базе хранятся хеши токенов, cookie — HttpOnly и SameSite=Strict.

Вход ограничен 8 попытками на IP за 15 минут и 40 попытками на учётную запись за 15 минут. Проверка старого пароля ограничена 5 попытками за 15 минут. Лимиты сохраняются в базе, перезапуск не сбрасывает блокировку; ответ 429 содержит `Retry-After`. После окончания окна вход снова доступен. Лимит входа учитывает и успешные попытки. Все административные API требуют действующую сессию.

## Тексты сообщений

В **Настройки магазина → Тексты уведомлений** выберите канал, отредактируйте шаблон, проверьте предпросмотр и сохраните. Переменные: `{номер_заказа}`, `{магазин}`, `{имя}`, `{телефон}`, `{состав_заказа}`, `{сумма}`, `{получение}`, `{комментарий}`. Каждая используется не более одного раза. В уведомлениях магазину обязательны номер, имя, телефон, состав, сумма и получение. В коротком сообщении клиенту состав заказа не поддерживается.

Шаблоны Telegram и WhatsApp сохраняются в снимке заказа: последующие изменения действуют для новых заказов, повторная отправка сохраняет исходный текст и разбиение на части. Ссылка клиенту в списке заказов использует текущий шаблон; ссылка в уже отправленном Telegram — шаблон на момент заказа. Текст WhatsApp для покупателя после оформления использует шаблон уведомления магазину.

Настройка текста не подключает внешние сервисы. Ключи подключения по-прежнему задаются на сервере по инструкциям ниже. Изменение текста не требует перезапуска. Для WhatsApp Business API меняется содержимое переменной одобренного Meta-шаблона, а не сам одобренный шаблон.

## Telegram

1. Создайте бота через BotFather.
2. Добавьте его администратором **закрытого канала для сотрудников** с правом публикации сообщений.
3. Заполните в `.env`:

```dotenv
TELEGRAM_BOT_TOKEN=значение_токена
TELEGRAM_CHAT_ID=-100xxxxxxxxxx
```

4. Перезапустите backend. Для уже созданных заказов нажмите «Повторить уведомления».

Сообщение содержит имя, телефон, наименования и варианты, цену каждой единицы, количество, суммы, адрес и комментарий. Номер телефона и кнопка под сообщением ведут в WhatsApp клиента с готовым текстом. Пользовательский текст экранируется. Длинный заказ отправляется несколькими сообщениями без удаления позиций.

## WhatsApp

**Обычная ссылка `wa.me` не отправляет сообщения автоматически.** На странице успешного заказа покупатель может открыть WhatsApp с готовым заказом и нажать «Отправить». В админ-панели такая же ссылка позволяет написать клиенту.

Для автоматического уведомления сотрудника подключите **WhatsApp Business Cloud API**:

```dotenv
WHATSAPP_TOKEN=значение_токена
WHATSAPP_PHONE_ID=идентификатор_номера_отправителя
WHATSAPP_RECIPIENT=77079565657
WHATSAPP_TEMPLATE=имя_одобренного_шаблона
WHATSAPP_TEMPLATE_LANGUAGE=ru
WHATSAPP_API_VERSION=v23.0
```

Нужен одобренный Meta шаблон с одной позиционной текстовой переменной в `body`. Пример структуры: `Уведомление магазина КИП и А: {{1}}. Свяжитесь с покупателем для подтверждения.` Переменная содержит данные заказа. Подключите собственный номер отправителя и подтверждённый номер сотрудника-получателя; версия API задаётся конфигурацией. Допуск шаблона, токен, согласие получателя и доступность номера настраиваются в Meta. Длинные заказы разбиваются на части, каждая отправляется через тот же шаблон.

Ключи не вводятся в браузере и никогда не возвращаются API. Индикатор «Настроен» означает наличие конфигурации, а не проверенную доставку. Статус уведомления «принято сервисом» означает успешный ответ API, а не факт прочтения: обработка delivery-webhook не входит в проект.

Очередь проверяется каждые 30 секунд, делает до пяти попыток с увеличением интервала. Уже успешно отправленные части не повторяются при обычном повторе. При обрыве после принятия внешним сервисом, но до фиксации результата, возможен повтор — внешние API не предоставляют транзакцию с нашей базой. Номер заказа помогает распознать такой дубль. Ошибка уведомления не отменяет заказ. После исчерпания попыток или добавления ключей доступна ручная повторная отправка в админ-панели.

## Структура и решения

```text
backend/app/
  schemas.py          Входные модели и валидация
  database.py         Соединения, схема, репозитории, первичное заполнение
  orders.py           Расчёты, транзакции, статусы, аналитика
  notifications.py    Адаптеры Telegram / WhatsApp и очередь
  message_templates.py Валидация, хранение, подстановка и предпросмотр сообщений
  security.py         Хеши паролей, сессии, ограничение попыток
  main.py             HTTP API, зависимости, защита запросов, раздача сборки
  seed.py             Демонстрационные товары и проверенные контакты
src/
  components/         Магазин, корзина, админ-панель и формы
  lib.ts              API-клиент и общие функции
  types.ts            Контракты данных
  styles.css          Темы и адаптивная сетка
backend/tests/        Тесты бизнес-правил и API
tests/e2e/           Проверки пользовательских сценариев в браузере
scripts/              Начальная настройка, резервное копирование, тестовый сервер
```

Обновление схемы при запуске сохраняет существующие товары и заказы. Категория услуг и единица `усл` добавляются один раз; пример сборки щита добавляется только при включённом демонстрационном каталоге. Новые базы по умолчанию создаются без демонстрационных товаров; для новой локальной демонстрации требуется `SEED_DEMO_DATA=true`. Значение `false` не удаляет существующие данные. Удалённая услуга не создаётся заново после перезапуска.

SQLite работает в WAL-режиме, операции изменения остатков используют `BEGIN IMMEDIATE`. Версия товара не позволяет старой открытой форме администратора перезаписать остаток, изменённый новым заказом. Снимки названий, цен и вариантов заказа сохраняются независимо от последующего редактирования каталога. Удаление товара или его варианта блокируется при активных заказах.

SQLite подходит для одного небольшого магазина на сервере с постоянным диском. Не размещайте базу на эфемерной файловой системе, сетевом файловом томе или нескольких независимых репликах. При масштабировании репозитории и очередь нужно перенести на PostgreSQL и отдельный worker. Список заказов в текущей панели показывает последние 1000 записей; аналитика учитывает все подходящие записи.

## Проверки

```bash
npm run build
npm run format:check
.venv/bin/python -m pytest backend/tests -q
.venv/bin/ruff check backend scripts
npm run test:e2e
```

Для проверки Python-форматирования установите `ruff` отдельно: `.venv/bin/pip install ruff`. E2E использует установленный Google Chrome, порт 8001 и отдельную временную базу. Реальные ключи мессенджеров в тестовом сервере отключены, запросы интеграций в unit-тестах заменены mock-ответами. Тестовые заказы не попадают в рабочую базу. Если Chrome отсутствует, установите браузер Playwright и измените `channel` в `playwright.config.ts`.

Тесты проверяют расчёт скидок, дробные метры, серверную цену, валидацию, повтор заказа, одновременную покупку последнего товара, откат остатков, отмену, ограничение входов, защиту origin, актуальность редактора, статусы, аналитику и формирование уведомлений. Дополнительно проверяются услуги без складского учёта, шаблоны сообщений и их безопасная подстановка, смена пароля и отзыв сессий. Браузерные сценарии покрывают покупку и обработку заказа, CRUD, поиск, избранное, тему, услуги, редактирование шаблонов и смену пароля. В Chrome проверяются ширины 320, 390, 768, 1024 и 1440 пикселей. Это не заменяет проверку на физических устройствах Safari/iOS/Android.

## Размещение на сервере

```bash
docker build -t kip-store .
docker run --name kip-store --restart unless-stopped \
  --env-file .env \
  -e DATABASE_PATH=/app/data/store.db \
  -e COOKIE_SECURE=true \
  -e ALLOWED_ORIGINS=https://ваш-домен.kz \
  -p 127.0.0.1:8000:8000 \
  -v kip-data:/app/data \
  kip-store
```

Перед контейнером нужен HTTPS reverse proxy. Прокси должен ограничивать размер запроса 5 МБ и передавать заголовки исходного адреса клиента. Настройте доверие Uvicorn к **точному IP вашего reverse proxy** через `--forwarded-allow-ips`, иначе ограничение попыток будет общим для всех клиентов за прокси. Не используйте `*` на публично доступном сервере. В разработке по HTTP оставляйте `COOKIE_SECURE=false`.

Домен, сервер и ключи интеграций в этой поставке не подключены. Docker-конфигурация подготовлена, но сборка контейнера требует установленного Docker и отдельной проверки на целевой платформе. Онлайн-эквайринга нет: оплата согласуется с менеджером.

## Резервное копирование

```bash
.venv/bin/python scripts/backup.py --database data/store.db --output data/backups
```

Это согласованная копия SQLite, которую можно делать при работающем приложении. Отдельно сохраняйте `data/uploads/` и секреты `.env`. Для восстановления остановите сервер, восстановите базу и изображения, удалите старые файлы WAL/SHM после штатного завершения сервера и снова запустите приложение. Резервные копии содержат персональные данные покупателей.
